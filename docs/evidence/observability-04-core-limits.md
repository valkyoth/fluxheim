# Commit 04: Core Dump Deployment Policy

Review base: `48f1828ce8d4e37b52f9d841ca08397cb2063738`.

## Finding And Fix

Fatal aborts, including the bounded-output watchdog, can cause OS memory dumps
containing secrets. Finite diagnostic reason strings do not sanitize the process
address space. The previously shipped service/container launch settings did not
explicitly set core-file limits to zero.

- Both server and ACME systemd services now set `LimitCORE=0`.
- Gateway and companion Compose examples set zero soft/hard core limits.
- Direct container commands in the deployment/renewal/release guides use
  `--ulimit core=0:0`; the ordinary Podman smoke checks both limits before exec.
- The container refresh smoke verifies `/proc/1/limits` on the running Fluxheim
  process after serving a successful HTTP request. Its existing refresh workflow
  therefore checks effective limits, not only the requested engine arguments.
- CI runs permanent service, Compose, guide and negative limit-parser tests.

No Rust, termination, authentication, filesystem security or dependency changes
are included. The watchdog fix and its eight subprocess cases remain intact.

## Validation

Local checks on 2026-10-23:

- Five deployment policy tests passed, including two real transient user-systemd
  services using the values read from the packaged units. Both children reported
  effective `RLIMIT_CORE` soft/hard limits `(0, 0)`.
- Real Podman HTTP smokes passed for existing `v1.8.3` full images: Wolfi,
  Alpine, Debian and SUSE Micro. Each live PID 1 reported zero soft/hard limits.
  These test launcher behavior; no new 1.9.0 images were built for this fix.
- The updated shell limit-check/config-validation sequence passed using the
  existing local development image.
- All 35 container-refresh regressions and four documentation-layout tests passed.
- The common fatal-path regression passed, including all eight subprocess cases.

The optional systemd test is reproducible with:

```bash
FLUXHEIM_TEST_SYSTEMD=1 python3 scripts/test_core_dump_policy.py
```

Ordinary CI runs the other four policy tests and explicitly skips the native
user-service test when no opt-in is set. Native Windows/macOS execution was not
repeated for these Linux deployment-only changes.

## Remaining Operator Responsibility

The next [Linux non-dumpable startup fix](observability-04-nondumpable.md)
closes the piped-collector gap for the three Fluxheim executables. The launcher
limits described here remain defense in depth.

Zero limits suppress ordinary core files, not necessarily host-piped collectors.
The [security guidance](../../SECURITY.md#fatal-termination-and-memory-dumps)
explains host collector policy, existing-dump retention, platform differences and
the need to restart/recreate existing deployments. No host-wide crash settings
were modified and no intentional memory dumps were generated by the deployment
smokes. Tests do not certify that a host cannot capture process memory.

Independent retest and GitHub checks remain gates before Commit 05.
